### Phase 1.4 — Algorithm delta (T1 + T2)

Replace the original 7-step algorithm with:
1. If `req.event_kind in BLOCKLISTED_KINDS` → return 422 `blocked/blocklisted_kind`.
2. Compute `payload_hash = payload_sha256(req.payload)`.
3. Compute tokens; **fetch last N=50 events from `source_agent`**, tokenize each, Jaccard. If any ≥ 0.9 → return 409 `deduplicated/jaccard_near_duplicate`. *(Jaccard before INSERT is fine — it's advisory; not race-safe but acceptable for demo scale per A1 commentary.)*
4. Compute `event_id = uuid4()`; `ts = req.ts or datetime.now(UTC)`.
5. **Open explicit transaction**:
   ```python
   with conn.cursor() as cur:
       try:
           cur.execute("BEGIN")
           insert_event(cur, ...)              # may raise IntegrityError on payload_hash conflict
           append_episodic(cur, ...)
           touch_semantic(cur, source_agent=...)
           if req.observed_agent:
               touch_semantic(cur, agent_id=req.observed_agent, ...)
           cur.execute("COMMIT")
       except duckdb.ConstraintException as e:
           cur.execute("ROLLBACK")
           if "payload_hash" in str(e):
               return PublishResponse(status="deduplicated", reason="exact_hash")
           raise
       except Exception:
           cur.execute("ROLLBACK")
           raise
   ```
6. Return 200 `{event_id, status:"stored"}`.

Storage helpers (`insert_event`, `append_episodic`, `touch_semantic`) take a `cursor` not a `conn` — they MUST NOT manage their own transaction.

`exists_by_hash` is **removed** from `app/storage/events.py` (no longer needed; UNIQUE constraint + IntegrityError handles dedup race-safely).

### Phase 1.4 — Tokenize specification delta (T3)

`tokenize(payload: dict) -> frozenset[str]` defined behavior:

| Input case | Behavior |
|---|---|
| `{}` empty payload | returns `frozenset()` — empty set |
| nested strings/lists | recurses, collects all string leaves |
| numeric/boolean/null leaves | excluded from tokens (only string leaves contribute) |
| string leaves | `s.lower().split()` — whitespace split, Unicode-safe (Korean words pass through as-is, no segmentation) |
| nested dict values | recursed; keys excluded |

`jaccard(a: frozenset, b: frozenset) -> float`:
- If `len(a) == 0 and len(b) == 0` → return `1.0` (treat both-empty as identical).
- Otherwise `len(a & b) / len(a | b)`.

`is_near_duplicate(new_tokens, recent_token_sets, threshold)`:
- If `len(new_tokens) == 0` → return `False` (empty payload near-duplication handled by UNIQUE hash, not Jaccard).

## 1. Requirements Restatement

Milestone 1 produces a runnable FastAPI service that accepts A2A `POST /publish` from a dummy agent, applies rule blocklist + Jaccard 0.9 dedup gates (no LLM), persists every surviving event to a DuckDB L0 `events` table with `source_type` provenance, exposes a standards-shaped `GET /agent-card`, and centralizes a cold-start signal (reflection_count == 0) usable by future `/query`. CREATE TABLE IF NOT EXISTS _schema_version (
```sql
  version    INTEGER PRIMARY KEY,

CREATE TABLE IF NOT EXISTS events (

  ts            TIMESTAMP NOT NULL,

CREATE INDEX IF NOT EXISTS idx_events_kind         ON events(kind);

CREATE TABLE IF NOT EXISTS entities_semantic (
  agent_id            VARCHAR PRIMARY KEY,
  aliases             JSON   NOT NULL DEFAULT '[]',
  traits_json         JSON   NOT NULL DEFAULT '{}',
  source_type         VARCHAR NOT NULL CHECK (source_type IN ('self','third_party','mutual')),
  corroboration_count INTEGER NOT NULL DEFAULT 0,
  first_seen_ts       TIMESTAMP NOT NULL,
  last_updated        TIMESTAMP NOT NULL
);

CREATE TABLE IF NOT EXISTS entities_episodic (
  id              UUID PRIMARY KEY,
  event_id        UUID NOT NULL REFERENCES events(event_id),
  observer_agent  VARCHAR NOT NULL,
  observed_agent  VARCHAR,
  kind            VARCHAR NOT NULL,
  ts              TIMESTAMP NOT NULL,
  source_type     VARCHAR NOT NULL CHECK (source_type IN ('self','third_party','mutual'))
);
CREATE INDEX IF NOT EXISTS idx_episodic_observed_ts ON entities_episodic(observed_agent, ts DESC);
CREATE INDEX IF NOT EXISTS idx_episodic_observer_ts ON entities_episodic(observer_agent, ts DESC);

CREATE TABLE IF NOT EXISTS reflections (
  reflection_id      UUID PRIMARY KEY,
  ts                 TIMESTAMP NOT NULL,
  scope              VARCHAR NOT NULL CHECK (scope IN ('agent','pair','society')),

  event_range_end    TIMESTAMP NOT NULL,
```

## Section 1 — Architecture findings

**A1. [P1] (confidence 9/10)** `app/api/publish.py` — **TOCTOU race on payload_hash dedup**
- Plan step 2: `if exists_by_hash(...) → 409`. Step 5: `insert_event(...)`. Between these, a concurrent same-hash request can pass `exists_by_hash` then both insert.
- Impact: silent duplicate events in L0. Citation chain later cites duplicate event_ids — narrative correctness gap.
- Fix: add `UNIQUE` constraint on `events.payload_hash` in migration. In handler, attempt INSERT first inside transaction; catch DuckDB `IntegrityError` → return 409 with reason `exact_hash`. Cheaper and race-free than check-then-insert.
- Maps to user pref: "explicit over clever" + edge case handling. DRY (no manual hash check needed).

**A2. [P1] (confidence 8/10)** Phase 1.4 — **Transaction boundary unspecified**
- Plan describes "transaction: insert_event + append_episodic + touch_semantic" but storage function signatures don't expose BEGIN/COMMIT. Must wrap in `publish()` handler.
- Risk: partial failure (insert events ok, append_episodic fails) → orphan event without observation row. L0/L1 consistency broken silently.
- Fix: handler uses `with conn.cursor() as cur:` + explicit `BEGIN; ... COMMIT;` (or DuckDB's `conn.begin() / commit() / rollback()` context manager). Storage functions accept connection, do NOT manage tx themselves. Add rollback-on-exception test.

**A3. [P2] (confidence 9/10)** README — **Uvicorn `--workers 1` mandatory for M1**
- DuckDB single-file is single-writer. Default uvicorn `--workers` may be >1 in production. Multi-process contend on file → corruption.
- Fix: README explicitly states `uvicorn app.main:create_app --factory --port 8080 --workers 1`. Phase 1.2 `Settings` notes single-writer constraint.

## Section 2 — Code Quality findings

## 1. Requirements Restatement

M2 turns the M1 ingest pipeline into a memory-aware system. Concretely:

1. Continue accepting `POST /publish` (M1 surface unchanged) — but each successful publish kicks off a **background reflection check** for three scopes: `agent` (source_agent), `pair` (source→observed if observed present), and `society` (global).
2. Each reflection scope has a **hybrid trigger**: fire when `events_since_last_reflection_for_(scope,subject) >= 10` OR `time_since_last_reflection_for_(scope,subject) >= 6h`. First reflection fires once threshold hit.
3. When triggered, the reflection scheduler calls the **cheap LLM tier** (Anthropic Haiku) with **prompt caching enabled**, persists a row in `reflections` table, and (for scope=agent or pair) **recompiles `entities_semantic.traits_json`** by merging the new reflection's structured output into the existing traits.
4. The **`AnthropicProvider` is wired** in M2 (was a stub in M1) — real HTTP call to Anthropic Messages API with `cache_control: {"type": "ephemeral"}` markers on the system prompt + recent reflection context. OpenRouter stays a stub until M3.
5. **`touch_semantic` is extended** to populate `aliases` (other agents that named this agent as `observed_agent`) — not just bump corroboration count.
6. **EVAL-1 baseline** harness exists and runs offline against a 5-case golden set. Real Anthropic calls only happen in `eval/`, never in `pytest` (CI uses mock).

**Out of M2** (re-deferred per PRD): `/query` endpoint, narrative renderer, 꼰대 persona prompt, content-grounded citation validator, EVAL-2/3 suites, OpenRouter activation, Docker. See §9.

## 1. Requirements Restatement

M3 turns the recorded events + reflections into a query-time narrative.

1. New endpoint `POST /query` — accepts a natural-language question + optional subject filter, returns a narrative response with inline citations.
2. Each narrative claim is grounded to a real `event_id` via inline `[↑e<short_id>]` markers. The validator rejects responses that cite an event_id absent from the `events` table.
3. The narrative uses the **expensive** LLM tier (Opus). Real Anthropic `claude-opus-4-7` wired through `AnthropicProvider` (existing M2 code), injected as `app.state.narrative_provider` in the same pattern as `app.state.reflection_provider`.
4. **Cold-start gating**: when `get_cold_start_state(conn).is_cold` is True, `/query` returns 200 with `COLD_START_FALLBACK_MESSAGE` and no LLM call. Honors the M1 helper.
5. **Retry on missing citation**: if validator rejects the response (cited event_id not found), re-prompt up to N=2 times. If still bad, return fallback.
6. **Tone**: neutral 3rd-person factual summarizer. **No 꼰대 persona.** Tone instruction in system prompt is bland: "당신은 다른 에이전트들의 행적을 객관적으로 요약하는 사회 기록자입니다."

**Out of M3** (re-deferred): content-grounded citation validator (LLM judge that compares narrative claim against cited event payload — M4), EVAL-2 (citation grounding 100-case harness — M4), EVAL-3 (persona consistency — N/A since persona dropped). OpenRouter activation deferred (M4/M5 dogfood cost decision).

```python
@router.post("/query", response_model=QueryResponse)
async def query(req: QueryRequest, request: Request) -> QueryResponse:
    conn = request.app.state.db
    provider = getattr(request.app.state, "narrative_provider", None)
    if provider is None:
        raise HTTPException(503, detail={
            "status": "unavailable", "reason": "narrative_provider_unconfigured"
        })
    result = await render_narrative(
        conn, provider, req.question, req.subject_agent,
        max_retries=2,
    )
    return QueryResponse(
        answer=result.answer,
        citations=result.citations,
        is_cold_start=result.is_cold_start,
        retries_used=result.retries_used,
    )
```

# Implementation Plan: oldman_agent v1 — Milestone 4 (Citation safety net: content-grounded validator + EVAL-2)

Generated 2026-05-20 by Opus (continuation after M3 ship). Source PRD: §1 item 6 + Delivery Milestone #4.

## 1. Requirements Restatement

M4 upgrades the existence-only citation check from M3 into a **content-grounded** check: when a narrative cites `[↑e<sid>]`, the validator confirms that the surrounding claim actually corresponds to the cited event's payload (not just that the event_id exists). This catches the "LLM cited a real event but the claim is fabricated" failure mode that the M3 existence check misses.

1. **LLM-judge validator** — new judge call that takes `(claim_sentence, event_payload)` → `{is_grounded: bool, reason: str}`. Uses **cheap tier (Haiku)** to keep cost low.
2. **Judge wiring** — extend `app/narrative/validator.py` with `async def validate_citations_with_judge(text, evidence, judge_provider) -> ValidationResult`. The existing existence-only `validate_citations` stays as-is; the new async version is opt-in via a kwarg on `render_narrative`.
3. **Renderer integration** — `render_narrative(... validator_mode="strict")` activates the judge; default `validator_mode="existence"` preserves M3 behavior. The /query endpoint defaults to `"strict"`.
4. **EVAL-2 harness** — 100 golden cases of `(question, evidence, narrative_with_citations, expected_hallucination_flag)`. Run mock-mode in CI; live-mode (real Anthropic Haiku judge) on demand. Pass criterion: **hallucination rate < 1%** on the golden set when the validator is enabled.
5. **Demonstrable block** — at least one EVAL-2 case shows the judge *catching* a fabricated claim that existence-check would have let through.
6. **Judge failure tolerance** — if the judge LLM call errors, the validator defaults to **existence-only** for that claim (graceful degradation, not blocking).

**Out of M4** (re-deferred): EVAL-3 (persona consistency — N/A, persona dropped at M3), Docker (M5), demo video (M5).

## 2. Risks & Open Decisions (M4-specific)

| # | Decision | Recommended call | Why | Fallback |
|---|---|---|---|---|
| 4.1 | Judge granularity | **Per-citation sentence** — extract the sentence containing each `[↑e<sid>]`, judge against the cited event payload | balances cost (1 judge call per citation) vs accuracy | per-paragraph if cost-sensitive |
| 4.2 | Sentence extraction | **Naive split on `[.!?]` followed by whitespace**; the sentence containing the marker is the claim under review | Korean text doesn't always end with western punctuation, but reflection-style prose typically does. Edge: marker at start/end of text | LLM-extracted sentence boundary if naive fails |
| 4.3 | Judge prompt format | Korean system + structured user msg: `claim` + `event_payload_json` → require JSON output `{"is_grounded": bool, "reason": str}` | parseable, cheap, deterministic via Haiku | retry on JSON parse fail (N=1) |
| 4.4 | Judge tier | **Cheap (Haiku)** | 100 cases × ~500 tok input × $0.80/1M ≈ $0.04 per `--live` run. Acceptable | Sonnet if recall too low |
| 4.5 | Judge concurrency | **Sequential per-citation** in M4 (gather() in M5 if latency is a problem) | predictable cost ceiling; demo scale | `asyncio.gather` later |
| 4.6 | Hallucination definition (EVAL-2) | A citation is "hallucinated" if **judge says `is_grounded=False`**. Hallucination rate = hallucinated_citations / total_citations across the 100 cases | matches PRD "hallucination < 1%" | tweak post-dogfood |
| 4.7 | What renderer does on judge-rejected citation | Treat the citation as invalid → trigger M3 retry loop (re-prompt with hint "이전 응답의 주장이 인용한 event 내용과 일치하지 않습니다.") | reuse existing retry infra | M5 may differentiate "missing" vs "ungrounded" retry hints |
| 4.8 | Live judge calls in pytest | **Forbidden** (same M2/M3 policy). Mock judge in tests. Real calls only in `eval/run_eval_2.py --live` | cost + determinism | — |
| 4.9 | EVAL-2 golden set composition | 100 cases: **70 grounded + 30 hallucinated**. 30 hallucinated cases include: invented agent names, mismatched timestamps, swapped roles, fabricated payload fields | exercises both branches of the judge | scale up if needed |
